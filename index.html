THE RAILS

RAIL = one of the two long strips down the edge of the breadboard. Everything plugged into a rail is one wire.

  1. 3V3 rail — header pin 17 to the breadboard + rail. Feeds screen VCC and screen LED. Nothing else.
  2. GND rail — header pin 39 to the breadboard − rail. Feeds screen GND and all three button diagonal legs.
  3. 5V (pins 2 and 4) — UNUSED. No wire in this build touches them. If one does, stop.
  4. SPI0 — BCM 10 MOSI (19), BCM 9 MISO (21), BCM 11 SCLK (23), BCM 8 CE0 (24). Fixed by the hardware; not yours to move.
  5. Chooseable pins — DC (BCM 24, pin 18) and RESET (BCM 25, pin 22) are picked in software. Move the wire, change the number in the code.

WARNINGS — READ BEFORE POWER

THE RULEWHAT HAPPENS IF YOU DON’T
GPIO pins are 3.3 V. They are not 5 V tolerant.5 V on any GPIO kills the SoC. Not a reset — a dead Pi.
No wire in this build goes into pin 2 or pin 4.Those two are 5 V. A wire there means you counted wrong.
Find pin 1 two ways: header end nearest the microSD slot, and its underside pad is SQUARE while every other pad is round.One row off and 3V3 becomes 5V.
Count the header in rungs, not pins. Rung N holds pins 2N−1 and 2N.Miscounting is the number one way this build dies. The buttons are on the last three even pins — count backwards from the corner: 40, 38, 36.
The silkscreen must say MSP2807. VCC to the 3V3 rail.Anything else is a different board and this sheet does not wire it. Stop and ask before you power up.
Power off before every wiring change: sudo shutdown -h now, green LED stops, then pull the USB.Hot-plugging shorts a rail for a few milliseconds. Enough to corrupt the card or take out a GPIO.
Buttons wire like Press = Light: one leg to the GPIO, the DIAGONAL leg to ground, no resistor.The pull-up is inside the Pi. Pressed reads LOW. Two legs of the same internal pair and the button does nothing.
Straight after boot, before any code runs, BCM 16/20/21 read pd | lo.The chip’s default pull-DOWN, not a stuck button. Do not report it as broken. It flips to pu | hi when the program sets the pull-up.
Pixels are free. A new part is parked until the prototype survives a reboot.A RADS counter costs nothing. A Geiger tube costs a part, a rail, a wire and three new ways to fail. Parked, not refused.

      GOAL — Three buttons read cleanly over SSH, with no screen and no resistors.

      # 01_button.py -- one button. Wire BCM 16 (pin 36) straight to GND (pin 39).
# Pull.UP means the Pi holds the pin HIGH itself. Pressing shorts it to GND.
# So: not pressed = True. Pressed = False. No resistor on the board.
import time
import board
import digitalio

btn = digitalio.DigitalInOut(board.D16)
btn.direction = digitalio.Direction.INPUT
btn.pull = digitalio.Pull.UP

while True:
    print("PRESSED" if not btn.value else "----")
    time.sleep(0.1)
      # 02_buttons.py -- three buttons, named once. ONE print per press, not fifty.
import time
import board
import digitalio

PINS = {"PREV": board.D16, "SELECT": board.D20, "NEXT": board.D21}   # pins 36 / 38 / 40

btns = {}
for name, pin in PINS.items():
    io = digitalio.DigitalInOut(pin)
    io.direction = digitalio.Direction.INPUT
    io.pull = digitalio.Pull.UP
    btns[name] = io

was = {name: True for name in btns}          # True = not pressed

while True:
    for name, io in btns.items():
        now = io.value
        if was[name] and not now:            # HIGH -> LOW is the press EDGE
            print(name)
        was[name] = now
    time.sleep(0.02)                         # 20 ms poll. Also the debounce.

      TEST — Press each switch once, slowly, while the print script runs. Then prove it at the pin:

        STAGE 4 WIRE DWELL 15 MIN · UNLOCKS → THE NAMELESS FRAME

        PHOSPHOR ONLINE

        GOAL — The screen lights, fills, and prints one line of text — driven from the laptop copy.

        1. Power down before touching the screen. Leave the switches wired.
        2. Prove MOSI is really MOSI first — the loopback below. Two minutes, saves an evening.
        3. Read the silkscreen: MSP2807. Anything else is a different board — stop. Then find VCC: it is the pad at the end of the 14-pin strip, farthest from the five touch pins. Count from there.
        4. Wire VCC, GND and LED only. Power up. Backlight should glow flat pale grey.
        5. Power down. Wire CS, RESET, DC/RS, SDI, SCK. Leave SDO and all five touch pads empty.
        6. Every screen wire is in FIG 2 and the pin table. Do not work from memory.
        7. Run 03_fill.py: whole panel, one flat colour.
        8. Run 04_draw.py: one line of text, top-left.

        READ BEFORE YOU POWER THE SCREEN

        • Swap SDI and SDO and nothing happens at all — backlight on, panel black. No error. Check pin 19 → SDI before you suspect the code.
        • CS goes to pin 24 and stays there. Never leave it unconnected — an unconnected pin picks up whatever voltage is nearby and changes on its own, so the screen samples clock edges it should ignore. The symptom reads exactly like a software bug.
        • DC and RESET are software’s choice; SPI0’s four pins are not. Move either wire without changing D24/D25 in the code and the panel stays black with the backlight lit.
        • The backlight is the biggest load on the 3V3 rail. Flicker or reboots when it lights = the wall adapter, not the wiring.
        • Pillow needs the absolute font path. Never ImageFont.load_default() — it is a tiny bitmap and it will make you think the screen is broken.

        TEST POINT — LOOPBACK (nothing wired to the screen yet)

        Power OFF, jumper pin 19 to pin 21, power ON.

        sudo apt-get install -y python3-spidev >/dev/null && python3 -c "import spidev;s=spidev.SpiDev();s.open(0,0);s.max_speed_hz=500000;print(s.xfer2([0xAA,0x55]))"

        [170, 85] with the jumper in. Then shut down, pull the jumper, boot, run it again: [0, 0] or [255, 255]. BOTH results must happen. [170, 85] both times means the jumper is in the wrong two holes and you are reading your own wire.

        TEST POINT — SCREEN POWERED (VCC, GND, LED only)

        vcgencmd get_throttled

        throttled=0x0, and the panel glows flat pale grey — backlight only, no image. Any other hex means the supply is sagging under the backlight: change the wall adapter, not the wiring. Panel completely dark means LED or VCC is in the wrong hole — recount the pads from VCC.

          STAGE 5 CODE DWELL 25 MIN · UNLOCKS → SOMETHING TICKS ALONE

          THE NAMELESS FRAME

          GOAL — One dict holds all truth, one loop runs, three buttons move a cursor across three deliberately unnamed tabs.

          1. One dict called STATE. Nothing else holds truth.
          2. STATE holds tab index and cursor index. Nothing else yet.
          3. Write draw(state) — takes the dict, sets pixels, returns nothing.
          4. draw() never changes STATE. Not once.
          5. One while loop. No sleep that blocks — compare monotonic() against a deadline.
          6. Read buttons in the loop: PREV and NEXT move the tab, SELECT enters.
          7. Label the tabs TAB_ONE, TAB_TWO, TAB_THREE. Leave them nameless. Naming is stage 8.
          8. Wrap the indexes with % instead of letting them run off the end.

          Three files, and the line between them is the whole architecture: hardware owns pins, screen owns pixels, main owns every decision.

# It does not know what the value MEANS. Rads climbing, HP draining, caps,
# a mission clock: same four lines. What it counts is not this file's business.

def tick(values, rates, dt, floor=0.0, ceil=999.0):
    """values, rates: {name: number}. dt: seconds since last call. Mutates values."""
    for name, rate in rates.items():
        v = values.get(name, 0.0) + rate * dt
        values[name] = min(ceil, max(floor, v))
    return values

import json, os, tempfile

PATH = os.path.expanduser("~/pipboy/state.json")
VERSION = 1

def write(state):
    """Temp file, then rename. A half-written save can never exist."""
    os.makedirs(os.path.dirname(PATH), exist_ok=True)
    fd, tmp = tempfile.mkstemp(dir=os.path.dirname(PATH))
    with os.fdopen(fd, "w") as f:
        json.dump({"version": VERSION, "state": state}, f)
        f.flush()                # push Python's buffer at the OS ...
        os.fsync(f.fileno())     # ... THEN force the OS to the card
    os.replace(tmp, PATH)
    d = os.open(os.path.dirname(PATH), os.O_DIRECTORY)   # the rename itself
    os.fsync(d); os.close(d)                             # has to be on the card too

def load():
    """The saved state, or None. A fresh start beats corrupted garbage."""
    try:
        blob = json.load(open(PATH))
    except Exception:
        return None
    return blob["state"] if blob.get("version") == VERSION else None

if __name__ == "__main__":
    write({"probe": 1}); print(load())

              The atomic temp-file-then-rename is what makes yanking the power safe — not saving often. Save every 10 seconds and on a real event, and the card lasts.
